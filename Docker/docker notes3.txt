Docker volume

volume is a storage mechanism used to persist data generated by and used by Docker containers. Volumes are managed by Docker and can be shared across multiple containers. They are stored outside the container’s filesystem, which allows data to persist even if the container is stopped or deleted.

3 Types

1.tmpfs Volumes
 tmpfs volumes are stored in the host system's memory, not on the disk. This means they are ephemeral and will be lost when the container stops.

2.Bind Mount
 Bind mounts are a way to mount a file or directory from the host machine into the container. These volumes allow you to directly access host files and can be useful for development or when you need to share specific files between the host and the container.
 docker run -it -v /host/path:/container/path ubuntu bash
 /host/path is like /ashu
 /container path is like /tosh

3.Volumes

 anonymous
 Anonymous volumes are similar to named volumes, but they are not given a specific name. Docker automatically generates a unique name for them when the volume is created. These volumes are typically used for temporary storage when you don’t need to persist data across container restarts.
 //docker run -it -v /path/in/container ubuntu bash

 named
 Named volumes are volumes that are given a specific name. They are stored in Docker’s default volume directory on the host machine (usually /var/lib/docker/volumes/). You can create and manage them by specifying a name when you create the volume or when you run a container.
 //docker run -it -v /path/in/container ubuntu bash

Any changes made inside /ashu in the container will reflect on the host machine, and vice versa.
permission of it are maintained by user so its less secure
