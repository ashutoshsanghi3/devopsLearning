image vs container
An image is essentially a snapshot of a file system and settings that you want to run inside a container.
It serves as a blueprint for creating containers.
we create image from dockerfile
image --> container

vm has snapshots and if we restore it,we won't lose it
docker container has snapshots which are stored differently from vm 
daemon in Linux is background process

docker containers are ephemeral,ephemeral is short lived and only if there is no process inside container
by default, container is in attached mode
docker container is just a process on the host machine

docker run -d nginx ->go in detached mode
docker run -it {image_name} bash -> create and get inside the container and inside it open bash
docker start {container_id} -> start the container
docker exec -it {container_id} bash -> execute the existing container and inside open bash
