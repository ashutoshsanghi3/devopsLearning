The Scheduler assigns unassigned Pods to worker nodes based on resource availability, constraints, and scheduling policies.

The Kubernetes scheduler is a crucial component of the Kubernetes control plane responsible for assigning Pods to Nodes. It ensures that Pods are matched to Nodes so that the Kubelet can run them. 

Kube-scheduler selects an optimal node to run newly created or not yet scheduled (unscheduled) pods.

In a cluster, Nodes that meet the scheduling requirements for a Pod are called feasible nodes. If none of the nodes are suitable, the pod remains unscheduled until the scheduler is able to place it.

differences for 6 namespaces in docker with kubernetes -> 

Pods share the same:

Network space (same IP address, same network interface).
File system space (same volume can be mounted on all containers in the pod).
IPC namespace (shared memory, semaphores, etc.).

Pods do not share the same:

Hostname (UTS namespace is separate).
User namespace (user IDs can be different).
Process (PID) namespace (separate by default but can be shared).

2 containers in a pod can talk to each other using localhost 

Why Pods Over Just Containers? ->

In theory, you could achieve some of these benefits in Docker by manually setting up shared networks and volumes.
However, Pods provide a built-in, standardized way to:
✔ Deploy multiple tightly coupled containers together
✔ Ensure network and storage sharing without extra configuration
✔ Simplify sidecar container patterns
✔ Improve scaling, scheduling, and load balancing

🚀 Think of a Pod as a "mini-host" that runs multiple containers as a single unit!
